# ESD-WORLD Masterplan: Complete Project Architecture

## 1. Project Purpose

**EndoESD-World** generates **synthetic Endoscopic Submucosal Dissection (ESD) video** by fine-tuning NVIDIA Cosmos foundation models on real ESD procedure footage. The motivation: real ESD video data is scarce, confidential, and difficult to share. Synthetic video can augment training datasets for surgical AI, enable procedural phase classification, and support surgical robotics simulation.

**Source data**: ~59 ESD videos from [/scratch/kcwp264/ESD_project_WUN24_confidential](file:///scratch/kcwp264/ESD_project_WUN24_confidential:0:0-0:0) (MPG format, clinical endoscopy recordings) + 355 additional videos captioned on NVIDIA Spark cluster.

**Target hardware**: AIRE HPC, 28 nodes × 3 NVIDIA L40S (48GB, PCIe, no NVLink).

## 2. Three-Track Architecture

### Track 1: EndoESD-World (Text→Video)
- **Model**: Cosmos3-Nano (16B MoT — Mixture-of-Transformers)
- **Fine-tuning**: LoRA SFT (rank=16, alpha=32) on diffusion generator attention modules (`q/k/v/o_proj_moe_gen`)
- **Input**: Text prompt → Output: Synthetic ESD video
- **Dataset format**: JSONL with `t2w_windows` (start_frame, end_frame, caption, caption_json)
- **Config**: [configs/vision_sft_esd_lora_nano.toml](file:///scratch/kcwp264/ESD-WORLD/configs/vision_sft_esd_lora_nano.toml:0:0-0:0) (primary) / [vision_sft_esd_full_nano.toml](file:///scratch/kcwp264/ESD-WORLD/configs/vision_sft_esd_full_nano.toml:0:0-0:0) (fallback full SFT)
- **Training**: `torchrun -m cosmos_framework.scripts.train --sft-toml=<config>` via `@/scratch/kcwp264/ESD-WORLD/slurm/train_lora_3gpu.sbatch`

### Track 2: EndoESD-Sim (Action→Video)
- **Model**: Cosmos-H-Surgical-Simulator (2B, flow-based diffusion transformer)
- **Base**: Fine-tuned on Open-H surgical benchmark; uses Cosmos-Reason1 as text encoder
- **Input**: Seed frame + 44D unified action vector → Output: Future video frames
- **Dataset format**: LeRobot v3 (parquet + MP4, 288×512, 16fps)
- **Action space**: 44D = left_xyz(3) + left_rot6d(6) + left_gripper(1) + right_xyz(3) + right_rot6d(6) + right_gripper(1) + reserved(24)
- **Training**: `torchrun -m scripts.train` in Cosmos-H-Surgical-Simulator repo via `@/scratch/kcwp264/ESD-WORLD/slurm/train_sim_3gpu.sbatch`

### Track 3: EndoESD-Transfer (Control→Video)
- **Model**: Cosmos-Transfer2.5-2B (ControlNet-style architecture)
- **Input**: Text + input video + control maps (edge/depth/seg/vis) → Output: Stylized/transferred video
- **Dataset format**: [videos/](file:///scratch/kcwp264/ESD-WORLD/datasets/esd_cosmos/videos:0:0-0:0) + [captions/](file:///scratch/kcwp264/ESD-WORLD/captions:0:0-0:0) + `edge/` + `depth/` + `seg/` directories
- **Training**: `torchrun -m scripts.train` in cosmos-transfer2.5 repo via `@/scratch/kcwp264/ESD-WORLD/slurm/train_transfer_3gpu.sbatch`

### Baseline: Cosmos-H-Surgical-Predict (Zero-shot)
- **Model**: 2B, image-to-video surgical world model (no fine-tuning)
- **Purpose**: Zero-shot comparison against fine-tuned tracks
- **Eval**: `@/scratch/kcwp264/ESD-WORLD/slurm/eval_baseline.sbatch`

### Additional Track: Cosmos-Predict2.5 LoRA (Surgical-Simulator base)
- **Model**: Cosmos-H-Surgical-Simulator as base, LoRA fine-tuned on ESD dataset
- **Dataset**: [datasets/esd_cosmos/](file:///scratch/kcwp264/ESD-WORLD/datasets/esd_cosmos:0:0-0:0) with [videos/](file:///scratch/kcwp264/ESD-WORLD/datasets/esd_cosmos/videos:0:0-0:0) (symlinks) + [captions/](file:///scratch/kcwp264/ESD-WORLD/captions:0:0-0:0) (JSON with long/short/medium)
- **Training**: `@/scratch/kcwp264/ESD-WORLD/slurm/train_cosmos_predict2_lora_3gpu.sbatch`

### ESD Phase Taxonomy (7 phases)
1. **Examination** — Endoscope surveys lesion and mucosal surface
2. **Marking** — Electrocautery dots delineate resection margin
3. **Injection** — Submucosal saline + indigo carmine lift
4. **Incision** — Circumferential mucosal cut
5. **Dissection** — Submucosal separation with electrosurgical knife
6. **Hemostasis** — Coagulation of bleeding vessels
7. **Retrieval** — Specimen extraction

Phase estimation uses temporal progress heuristics (e.g., progress < 0.10 → examination, 0.40–0.75 → dissection).

## 10. Key Design Decisions

- **Mode collapse prevention**: LoRA-only training with `keys_to_select=["lora_"]`, EMA disabled, grad clip 0.1, LR 5e-4 (LoRA-appropriate)
- **L40S compatibility**: All NCCL P2P/IB disabled, Socket networking, expandable CUDA segments
- **Duration constraint**: SFT dataloader skips videos > 61s; all windows capped accordingly
- **Synthetic actions**: Phase-specific 44D action profiles with realistic translation/rotation scales (e.g., dissection has highest translation_scale=0.012)

## AIRE HPC — Key Facts

**Hardware**

- 84 GPU cards total
- Login nodes have entry-level A2 GPUs (config only — **don't run jobs on login nodes**)

**Slurm Submission**
- Scheduler: **Slurm** (replaced SGE on old ARC3/ARC4)
- GPU jobs: `--partition=gpu --gres=gpu:l40s:N` (N = 1, 2, or 3)
- 1 GPU defaults to **1 CPU core + 1GB RAM** — must explicitly request more:
  - `#SBATCH --cpus-per-task=8` (≈8 cores per GPU)
  - `#SBATCH --mem=64G` or `--mem-per-cpu=8G` (≈85GB per GPU)
- `sbatch script.sh` for batch, `srun -p gpu --gres=gpu:1 --pty /bin/bash` for interactive
- **Fair share** scheduling (not FCFS) — spread submissions throughout a project, not in bursts

**Environment**
- `module load miniforge` → conda for Python envs
- Your envs: `endofm-lv` (surgical video/MOT), `cudaq-env` (CUDA-Q/quantum)
